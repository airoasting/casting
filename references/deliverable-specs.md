# 산출물 명세 · 결과물 종류별 기본 완료 기준

> 팀장이 ②에서 팀을 짠 직후, 이번 요청의 산출물마다 명세를 쓸 때 본다. 작성 팀원과 독립 검토자가 **같은 명세**를 받는다. 작성자가 모르는 기준으로 검토자가 떨어뜨리는 일을 없애기 위해서다.
> 이 파일은 손으로 쓴다(`sync_refs.py`가 생성하지 않는다).

## 왜 필요한가

iteration-2의 실제 실행 두 번에서 나온 결함의 대부분은 작성자가 받은 적 없는 기준이었다. "1페이지"가 몇 자인지, 진단이면 항목마다 판정 기준이 있어야 하는지, 메일이 요청한 행동마다 받을 양식이 있어야 하는지를 검토자만 알았다. 그리고 검토자가 명세에 없던 것(부록, 설문 첨부)을 요구하고, 그걸 보강하다 2차에서 새 결함이 생겼다. 명세는 이 두 가지를 막는다.

## 명세 형식 (산출물마다 하나)

```
### <문서 제목>
독자와 쓰임: <누가, 어떤 장면에서, 읽고 무엇을 하는가>
분량 상한: <글자 수(공백 포함) 또는 장수. 아래 표의 기본값에서 시작>
필수 요소: <빠지면 결함인 것. 아래 표의 기본값 + 사용자가 콕 집은 항목>
하지 않을 것: <범위 밖. 예: 회사 내부 수치를 추정해 채우기>
다른 산출물과 맞출 것: <공유하는 숫자·용어·목록·일정. 산출물이 하나면 생략>
```

명세는 짧게 쓴다. 산출물 하나에 10줄을 넘기지 않는다. 사용자가 분량·형식을 정해 줬으면 그 값이 기본값보다 우선한다. 아래 표의 필수 요소와 공통 품질 조건은 빼지 않고 옮긴다(뺄 때는 이유를 적는다). 산출물은 "산출물 A" 같은 라벨이 아니라 문서 제목으로 부른다.

## 결과물 종류별 기본값

분량은 공백 포함 글자 수다(`python3`의 `len()`으로 센다. `wc -m`은 쓰지 않는다). A4 1장은 표를 포함해 약 1,800자로 본다. 첫 작성은 상한의 90% 안을 목표로 한다.

**모든 산출물에 공통인 품질 조건**: 한 문서 안에서 같은 대상은 같은 용어·숫자로 쓴다. 날짜는 절대 날짜로 쓰거나, D-n을 쓰면 영업일인지 역일인지 한 번 밝힌다. 처음 나오는 지표·용어는 한 줄로 정의한다(예: "정기 사용자 = 주 3일 이상 사용"). 다음 행동은 **그 문서의 독자**가 할 일이다. 작성·발송 주체의 할 일은 문서에 넣지 않는다.

| 종류 | 분량 상한 | 필수 요소 |
|---|---|---|
| 1페이지 보고·진단·브리핑 | 1,800자. 넘치는 근거·출처 목록은 별첨으로 | 결론 3줄 이내를 맨 앞에. 주장마다 근거(출처와 기준 시점). 진단·평가면 **항목마다 판정 기준**(무엇이면 양호/주의/위험인지). 판정 기준은 등급끼리 겹치지 않고 빈칸이 없어야 한다(어떤 값이든 정확히 한 등급에 들어감). 판정에 쓰는 값은 수집 계획에 모두 들어 있어야 하고, 판정 결과를 적을 칸이 있어야 한다. 다음 행동(누가·무엇·언제) |
| 이사회·경영진 보고서 | 본문 앞 2장(약 3,600자)에 결론과 의결 사항. 나머지는 별첨 | 의결 안건마다 선택지·권고안·근거·비용·리스크. 지난 결정과 달라진 점 |
| 분석 보고서(시장·경쟁·재무·데이터) | 본문 5,000자 | 결론 먼저. 수치마다 출처·기준 시점·정의. 가정과 사실 분리. 시사점이 행동 권고로 이어짐 |
| 업무 메일·안내 메일 | 본문 700자(제목·서명 제외). 짧은 버전을 따로 낼 수 있음 | 제목 후보. 첫 두 문장에 요청과 기한. **요청한 행동마다** 방법·기한·양식(설문이면 문항 자체). 발송일과 회신에 주는 기간(영업일 수). 첨부를 말하면 첨부가 실제로 있음. "발송 전 채울 칸" 목록을 본문과 분리 |
| 사내 공지 | 800자 | 무엇이 언제부터 바뀌는지, 영향 받는 대상, 해야 할 일, 문의처 |
| 회의록 + 할 일 | 회의록 1,500자, 할 일은 표 | 결정·논의·미결을 구분. 할 일마다 담당·기한·근거 발언. 자료에 없는 담당·기한은 "미정"(지어내지 않음) |
| 제안서·사업계획서 | 사용자 양식이 있으면 그 양식. 없으면 본문 8,000자 | 평가 기준(또는 상대의 요구) 대응표. 예산 산식과 근거. 일정과 산출물. 수행 역량의 근거 |
| 보도자료 | 1,500자 | 헤드라인, 리드 문단(누가·무엇·언제·어디서·왜), 인용 1~2개, 회사 소개, 문의처 |
| 발표 슬라이드·카드뉴스 | 장수는 사용자 지정, 없으면 슬라이드 10장·카드 8장 | 장마다 메시지 하나. 첫 장에 결론. 수치에 출처 |
| 설문·평가 설계 | 문항 15개 | 문항마다 측정 목적과 결과의 쓰임(어느 판단에 들어가는지). 응답 형식. 익명 여부 |
| 계약·정책 검토 | 3,000자 | 조항별 리스크 등급, 근거 조항, 수정 문안, 협상 우선순위. 자문이 아니라는 고지 |

## 명세를 쓸 때 지키는 것

- **필수 요소는 목적에서 나온 것만 넣는다.** "있으면 좋은 것"은 넣지 않는다. 명세가 부풀면 분량 상한과 부딪힌다.
- **`[확인 필요]`는 사실·값의 자리에만 쓴다.** 새 입력 없이 작성할 수 있는 것(설문 문항, 판정 기준 초안, 문구, 양식)은 비워 두지 않고 쓴다. 명세의 필수 요소에 이 구분을 적어 둔다.
- **산출물이 둘 이상이면 "다른 산출물과 맞출 것"을 반드시 적는다.** 예: 메일이 진단을 첨부하면 진단의 항목 이름·수집 목록·기한이 메일과 같아야 한다.
- **내부 데이터가 없어 범위를 바꿀 때**(SKILL.md ④)는 명세에서 바꾼다. 예: "진단 1페이지" → "진단 틀 + 공개 기준선 + 수집 계획 1페이지". 바꾼 사실은 최종 결과의 범위 줄에 밝힌다.

## 검토자가 명세를 쓰는 법

- 판정은 **사용자의 목적과 명세**에 대고 한다.
- 명세에 없는 새 요구(부록 추가, 별도 문서, 추가 분석)는 결함이 아니라 **제안**으로 적는다. 제안은 판정에 넣지 않는다.
- 다만 명세 자체가 목적을 못 채우면(예: 이사회 보고인데 의결 사항이 필수 요소에 없다) 그 빈틈은 `[내용]` 결함으로 적고, 목적의 어느 부분이 빠지는지 근거를 댄다.
